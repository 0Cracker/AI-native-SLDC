# 00 Intake

- **입력** 요청, 저장소 지침, 기존 문서·검사, 운영 이슈.
- [인터뷰](../planning-interview.md)로 이번 변경의 사용자, 문제, 성공 목표, 포함 범위와 제외 범위, 착수 위험과 권한을 확인한다. 관찰 가능한 기대 동작과 인수 조건을 확정할 때는 01을 적용한다. 기존 변경인지 확인하고 [산출물 경로](../artifact-layout.md)를 정한다.
- 현재 문제의 근거, 원하는 결과와 성공 판단 방법을 구분한다. 해결 방향을 바꿀 제약이나 미결을 먼저 확인한다.
- 작은 변경은 [축약 경로](../compact-routes.md)로 필요한 기록과 기존 근거를 고른다.

| 경로 | 추가 확인 |
|---|---|
| Feature, 소규모 변경 | 사용자 결과와 재사용할 요구·설계·검사 |
| Bugfix, Hotfix | 재현, 의도된 동작, 회귀. Hotfix는 권한 내 안정화, 복구와 사후 보강 |
| Refactor | 유지할 계약, 불변조건과 비교 기준선 |
| Migration | 무결성, 호환성, 손실 위험과 복구 |
| 기술 제약 출발 | 제약과 타당성 확인 후 01에서 요구 확정 |
| Spike, PoC | 가설, 시간 제한, 관측과 판정. 제품 반영 여부와 결과를 기록 |

- **기록** 기존 이슈나 변경 기록을 우선한다. 별도 기록이 필요하면 [요청 정의](../../assets/templates/intake.md), [기술 검증 기록](../../assets/templates/spike-report.md), [배포 기록](../../assets/templates/release.md) 중 관련 틀을 사용한다.
- **종료** [G0](../lifecycle.md#단계별-종료-조건) 이후 필요한 단계로 진행한다. Spike·PoC는 실험 결과와 반영 판단으로 끝낸다. 제품에 반영할 때는 실험 근거를 재사용한다.
- Hotfix에서 이미 권한이 부여된 중단·롤백 등 안정화가 필요하면 실행 범위, 권한, 버전·시각, 결과를 배포·운영 기록에 남긴다. 신규 수정에는 변경 영향에 따른 검증을 적용한다.
