# 06 검증과 수락

- **입력** 대상 리비전, 인수 조건, 설계·계약, Task와 실행 증거.
- **06a** 관련 통합 검사를 선행 조건에 맞춰 실행하고 실제 연결, 환경, 리비전과 결과를 기록한다. 검증 대상 경계가 바뀌면 영향을 받는 설계와 검사를 다시 확인한다.
- **06b** Feature 전체 인수 조건, 품질, 경계 간 회귀와 명세 일치를 확인한다. 영향에 따라 성능·보안·접근성·AI 평가를 추가한다.
- 사용자와 프로젝트 요구, 변경 위험을 기준으로 독립 검증의 적용 여부와 범위를 확인한다. 적용되면 확정 사양과 대상 리비전을 기준으로 구현과 분리된 증거를 확보한다. 필수 독립 검증을 수행할 수 없으면 차단 사유를 기록한다.
- 결함은 요구·기대값, 구조, 상세 설계·계약, 계획, 코드, 테스트 환경으로 분류한다. 코드 결함은 재현과 필요한 회귀 검사 후 05로 보낸다. 수정 뒤 영향 범위를 재검증한다.
- **기록** 대상 리비전, 결과와 증거, 잔여 위험, 해당하는 수락 판정을 기존 PR이나 검증 기록에 남긴다. 별도 문서가 필요하면 [검증 기록 틀](../../assets/templates/verification.md)을 사용한다.
- **종료** 적용한 [06a와 G6](../lifecycle.md#단계별-종료-조건)를 각각 판정한다. 배포가 요청 범위에 포함되면 07에 연결한다.
