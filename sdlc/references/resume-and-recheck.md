# 변경 후 재검증과 작업 재개

1. 현재 제품 명세와 해당 변경의 `index.md`부터 읽는다. 진행 중이거나 재개 조건이 충족된 보류 작업은 같은 ID를 쓴다. 완료 후 별도 문제는 [새 변경](artifact-layout.md#변경-단위와-상태)으로 연결하고 관련 과거 기록만 읽는다. 정본과 증거를 실제 코드, 환경 리비전에 대조한다.
2. 요구, 결정, 계약, 코드, 검사, 환경 또는 데이터가 바뀌면 관련 ID와 변경 전후 버전을 기록한다. 관계 지도를 따라 영향을 받는 Increment, Task, Gate와 증거를 식별한다.
3. 영향받는 기록은 **재검증 대기**로 표시한다. 이는 현재 근거의 유효 상태다. 이전 판정과 실행 결과는 당시 범위·리비전과 함께 보존한다. 영향받지 않은 증거를 재사용할 때는 적용 범위와 유지 근거를 남긴다.
4. 원인이 되는 단계에서 보강한다. 요구·기대값은 01, 경계·책임은 02, 상세 설계·계약·검사 명세는 03, 계획은 04, 구현은 05로 돌아간다. 환경 변경은 해당 검사와 판정을 다시 확인한다.
5. 영향받는 검사와 판정을 새 리비전에 연결한다. 재검증 대기 상태가 해소되면 새 판정을 기록한다. 대기 상태가 남은 Gate는 다음 단계의 통과 근거로 사용하지 않는다.

기존 변경 기록에 영향을 받는 결정과 검사, 증거 적용 범위, 재개 지점과 차단 사유를 남긴다. 실행 결과는 기존 CI나 검증 정본에 연결한다.
