# 축약 경로

00에서 요청 유형과 변경 영향을 확인한다. 사용자가 요청한 범위, 기존 계약, 데이터·권한·운영 위험을 기준으로 필요한 단계와 증거를 정한다. 신규 결정이 필요한 영역은 해당 단계에서 보강한다.

| 변경 유형 | 새로 남길 최소 기록 | 기존 근거로 충족할 수 있는 조건 |
|---|---|---|
| 공개 행동·구조 변경이 없는 문서 정정 | 수정 범위, 관련 정본, 확인 결과 | 기존 정본이나 이슈에 기록한다. 제품 코드·계약이 그대로라면 신규 Feature 설계나 제품 실행 검사는 적용하지 않는다. 문서 링크·내용 등 해당 검사를 한다. |
| 경계·계약을 유지하는 Bugfix | 재현, 의도된 행동, 수정 범위, 회귀 검사와 변경 전후 결과 | 01은 유효한 인수 기준, 02는 유지되는 책임·경계와 그림, 03은 관련 동작·검사 명세 참조와 변경점으로 충족할 수 있다. |
| 동작을 유지하는 Refactor | 유지할 계약·불변조건, 변경 범위, 통과 기준선과 동등성 검사 | 구조와 책임이 그대로면 G2의 기존 근거를 재사용한다. 내부 책임이나 의존성이 달라지면 해당 구조·설계를 갱신한다. |
| 경계·계약·데이터·권한·운영 위험이 달라지는 변경 | 변경된 영역의 결정, 계약·그림, 테스트 명세와 필요한 통합·복구 증거 | 영향 없는 부분의 근거만 재사용한다. 요청 유형이 작거나 긴급해도 변경된 경계와 위험을 판단한다. |

- 신규 Feature는 [산출물 구조](artifact-layout.md)를 기본으로 한다. 기존 변경은 이슈·정본·기능 폴더를 재사용하고, 필요한 기록만 추가한다.
- 단계별로 **직접 작성·갱신**, **기존 근거 참조**, **적용 없음**을 구분한다. 기존 문서가 현재 범위·버전에 맞는 이유와 남은 확인을 링크한다. 적용하지 않는 검사에는 영향이 없다는 근거를 적는다. 필요한 검사나 결정이 빠진 상태는 차단 또는 승인된 예외로 처리한다.
- G2·G3는 변경되지 않은 영역에 유효한 기존 그림을 참조한다. 변경 영역에는 [그림 규칙](diagram-policy.md)을 적용한다.
- 작업이 작아도 재현, 결정적 변경의 구현 전 실패, 리팩터링 기준선, 관련 회귀 등 [종료 조건](lifecycle.md#단계별-종료-조건)에 필요한 근거는 유지한다. 통합 대상이 없으면 03-H에 이유를 기록하고 06a에서 확인한다.
- 축약 판단은 `intake.md` 또는 기존 정본에 적는다. 단계별 판정과 증거는 [Feature 관계 지도](../assets/templates/shared/index.md)나 기존 변경 기록에서 찾을 수 있게 한다.
