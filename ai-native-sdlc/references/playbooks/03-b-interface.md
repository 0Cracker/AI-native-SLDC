# 03-B 인터페이스와 계약 설계

- **적용** API, RPC, 이벤트, Tool과 외부 연동 계약 변경.
- **입력** Increment 요구·인수 조건, 기존 계약·버전, 호출자.
- 제공자·호출자·책임을 식별한다. 변경 전후 의미, 필수 필드·타입·오류·권한을 대조한다.
- 정상 입출력과 오류, 타임아웃·재시도·중복·순서·부작용을 정한다. 미결 호환성은 먼저 확인한다.
- 혼합 버전, 전환, 중단과 복구 조건을 기록한다. 호출 관계를 설명하는 데 도움이 되면 정상과 실패 흐름을 [그림](../diagram-policy.md)에 연결한다.
- 정형 계약을 갱신하고 제공자·호출자, 호환성, 관련 오류·중복 검사를 정의한다. 상태·복구는 03-C·G와 맞춘다.
- **산출물** `designs/D001-*.md`의 [인터페이스 명세](../../assets/templates/interface-design.md), [시퀀스 예시](../../assets/templates/interface-sequence.mmd), 정형 계약과 검사 ID. [저장 경로](../artifact-layout.md)를 따른다.
- **완료** 영향받는 호출자, 계약, 정상·실패 흐름, 호환성 및 검사 근거가 일치한다.

## 변경 유형별 판단

| 변경 | 결정할 내용 | 검증 근거 |
|---|---|---|
| 응답 필드 추가 | 필수 여부, 값이 없는 경우, 기존 호출자의 알 수 없는 필드 처리 | 기존·신규 호출자의 실제 역직렬화와 정상·누락 응답 검사 |
| 필드 삭제·이름·타입·의미 변경 | 영향받는 호출자, 버전 공존이나 전환 순서, 복구 가능 시점 | 구·신 호출자와 제공자 조합에서 지원하기로 한 계약 검사 |
| 오류·권한 변경 | 호출자가 오류를 구별할 방법, 재시도 가능 여부, 보호 데이터 노출 여부 | 오류 응답과 호출자 분기, 권한 거부와 응답 내용 검사 |
| 상태 변경 호출의 타임아웃·재시도 | 원래 요청의 반영 여부가 불명확할 때의 조회·재시도 조건, 중복 방지 기준 | 같은 요청 재전송, 응답 유실, 중복 도착에서 합의된 결과 확인 |
