# 03 상세 설계

- **입력** 요구·인수 조건·기대값 근거, 상위 구조와 계약, 현재 Increment 범위.
- 변경 영향을 기준으로 A~H와 필요한 확장 영역을 선택한다. `Required`는 작성·갱신, `Referenced`는 유효한 참조, `N/A`는 영향 없음, `Waived`는 승인된 예외다. 이유와 근거를 적고 C·H는 항상 확인한다.
- 정상·실패 흐름, 경계, 계약과 영역 간 영향을 설계한다. 중요한 미결은 그림과 예시를 놓고 [인터뷰](../planning-interview.md)로 확인한다.
- 각 D 문서는 해결할 설계 문제, 선택한 규칙과 근거, 유지할 불변조건을 구분한다. 정상·경계·실패를 검사 ID에 연결한다.
- 영향 영역별 [그림](../diagram-policy.md)을 설계·계약·검사에 연결한다. H의 기대값은 승인된 요구, 규격, 독립 데이터나 계산식에서 구한다.
- **기록** 상세 설계 단위마다 `designs/D001-*.md`에 관련 R·A ID, Increment, 영역, 그림·계약·검사를 연결한다. [관계 지도](../../assets/templates/shared/index.md)에 영역 선택과 근거를 남기고, 검증은 [테스트 명세](../../assets/templates/03-detailed-design/test-plan.md)에 둔다.
- **전환** [G3](../lifecycle.md#단계별-종료-조건) 충족 후 Increment ID, 선택 근거, 계약과 검증 조건을 04로 넘긴다.

## 확장 영역 추가

1. A~H를 함께 적용해도 독립적인 정책·결정·검증이 남으면 영역 이름과 이유를 정한다. 적용 범위나 정책이 미결이면 사용자에게 먼저 확인한다.
2. [확장 설계 작성 틀](../../assets/templates/03-detailed-design/extended-design.md)로 별도 `designs/D001-*.md`를 만들고, 영역 이름을 `확장 / <영역명>`으로 기록한다.
3. 관계 지도에 확장 영역의 선택과 정본을 추가한다. 관련 R·A, 기존 A~H 영역, 영향 영역의 그림, 계약과 검사 ID를 연결한다. 기존 문서에 같은 결정을 복사하지 않는다.
4. 확장 영역에도 G3를 적용한다. 정책, 예외·실패 동작, 그림·계약과 검사 근거가 맞으면 구현 Task로 넘긴다.
