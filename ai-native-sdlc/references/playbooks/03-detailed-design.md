# 03 상세 설계

- **입력** 요구·인수 조건·기대값 근거, 상위 구조와 계약, 현재 Increment 범위.
- 변경 영향을 기준으로 A~H와 필요한 확장 영역을 선택한다. 관계 지도를 쓰는 경우 `Required`는 작성·갱신, `Referenced`는 유효한 참조, `N/A`는 영향 없음, `Waived`는 승인된 예외로 기록한다.
- 정상·실패 흐름, 경계, 계약과 영역 간 영향을 설계한다. 중요한 미결은 [인터뷰](../planning-interview.md)로 확인한다.
- 각 D 문서는 해결할 설계 문제, 선택한 규칙과 근거, 유지할 불변조건을 구분한다. 정상·경계·실패를 검사 ID에 연결한다.
- [그림](../diagram-policy.md)이 필요한 경우 설계와 연결한다. 검사 기대값은 승인된 요구, 규격, 독립 데이터나 계산식에서 구한다.
- **기록** 기존 설계나 PR에 영역 선택, 관련 요구와 구조 결정, 계약과 검사를 연결한다. 별도 산출물이 필요하면 [관계 지도](../../assets/templates/index.md), `designs/D001-*.md`, [테스트 명세](../../assets/templates/test-plan.md)를 사용한다.
- **종료** [G3](../lifecycle.md#단계별-종료-조건)을 확인하고 계약과 검증 조건을 필요한 계획이나 구현에 연결한다.

## 확장 영역 추가

1. A~H를 함께 적용해도 독립적인 정책·결정·검증이 남으면 영역 이름과 이유를 정한다. 적용 범위나 정책이 미결이면 사용자에게 먼저 확인한다.
2. [확장 설계 작성 틀](../../assets/templates/extended-design.md)로 별도 `designs/D001-*.md`를 만들고, 영역 이름을 `확장 / <영역명>`으로 기록한다.
3. 확장 영역의 선택과 정본을 연결한다. 관련 요구와 설계, 계약, 검사와 필요한 그림을 참조한다.
4. 확장 영역에도 G3를 적용한다. 정책, 예외·실패 동작, 계약과 검사 근거가 맞으면 구현에 반영한다.
