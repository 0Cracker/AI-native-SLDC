# 01 요구사항과 인수 조건

- **입력** 요청 요약, 재현, 기존 계약.
- 사용자 시나리오, 기능·품질 요구, 업무 규칙에 ID를 부여한다. 정상·경계·오류와 유지할 행동을 구분한다.
- 시나리오마다 사용자 또는 호출자의 목표, 주요 흐름, 우선순위와 독립 확인 방법을 적는다. 시나리오를 구현 파일보다 먼저 정한다.
- 핵심 요구마다 전제, 동작, 기대 결과, 독립 기대값 근거를 연결한다. 품질 조건은 환경, 측정 방법, 임계값과 단위를 적는다.
- 기대값은 요구·규격·참조 데이터·별도 계산처럼 검증 대상 구현과 독립적인 근거에서 가져온다. 출처와 적용 버전을 연결한다.
- Bugfix는 현행 결과와 의도된 동작을 구분한다. Refactor는 유지할 행동과 비교 기준선을 기록한다.
- 기대 행동, 계약 충돌과 중요한 미결은 [인터뷰](../planning-interview.md)로 해결한다.
- **기록** [요구사항](../../assets/templates/requirement.md)을 `requirements/R001-*.md`처럼 요구별로 작성한다. Intake·시나리오·인수 조건·기대값 근거와 관련 요구를 연결한다.
- **전환** [G1](../lifecycle.md#단계별-종료-조건) 충족 후 02.
