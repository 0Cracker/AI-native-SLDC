# 04 작업 계획

- **입력** G3를 충족한 Increment, 설계, 계약, 그림과 검증 명세.
- 요구 → 설계·계약 → 검사 사이의 누락과 충돌을 찾는다.
- 동작 단위로 분해한다. 선행 계약, 이행, 구현, 검증 순서를 정한다. 파일이 겹치면 순서나 소유권을 정한다.
- Task마다 Increment, 목표, 입력, 수정 범위, 의존성, 완료 조건과 검사 ID를 기록한다. 관련 요구·설계·계약의 정본을 연결하고 계약·기대값 변경 권한을 구분한다.
- 완료할 코드·산출물과 통과할 검사를 구분한다. 03-H에서 정한 검사 ID를 배정하고, 검사가 빠졌거나 모호하면 03-H로 돌려보낸다.
- 테스트 작성과 구현 담당, 쓰기 범위, 인계 조건을 기록한다. 별도 담당 또는 에이전트 사용을 권장한다. 같은 담당이라면 기대값 출처와 구현 전 검증 증거를 분리한다.
- 직렬·병렬 작업 모두 Increment의 통합 순서, 선행 Task와 06a 검사 ID를 정한다. 통합 대상이 없으면 G3의 생략 근거를 연결한다.
- 병렬 작업은 의존성과 수정 범위가 충돌하지 않는지 확인한다. 공유 파일·계약의 조정 방법을 기록한다.
- 첫 Task의 환경, 테스트 데이터와 접근 권한을 확인한다.
