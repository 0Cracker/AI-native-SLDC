# 듣는 사람의 눈높이로 설명하기 (ELI5)

복잡한 주제도 누구나 이해할 수 있게 풀어 설명한다. 듣는 사람의 배경지식, 어휘 수준, 관심사에 맞춰 설명한다.

## 1단계. 설명을 듣는 사람 파악하기

사용자의 요청에서 누구에게 설명하는지 파악한다. 다음 범주를 참고한다.

### 나이

| 대상 | 설명 방식 |
|---|---|
| 5세 | 아주 쉬운 단어와 짧은 문장을 쓴다. 장난감, 동물, 사탕, 놀이터로 재미있게 비유한다. “크레파스 한 상자가 있다고 생각해 봐.” |
| 10세 | 초등학생 수준에 맞춘다. 간단한 원인과 결과를 설명할 수 있다. 학교, 운동, 비디오 게임을 예로 든다. |
| 15세 | 어느 정도 추상적인 내용을 다룰 수 있다. 소셜 미디어, 휴대전화, 게임을 예로 들고 조금 편한 말투를 쓴다. |
| 20~30세 | 분명하고 직접적으로 설명한다. 일상, 직장, 돈과 관련된 실제 사례로 비유한다. |
| 40세 이상 | 존중하는 말투를 쓴다. 집 마련, 직장 생활, 가정생활에 빗댄다. |

### 학년과 교육 수준

| 대상 | 설명 방식 |
|---|---|
| 초등학교 5학년 | 쉬운 단어와 구체적인 예를 쓰고 전문 용어는 피한다. “이런 상황이라고 생각해 봐.” |
| 중학생 | 기본 용어를 소개하고 뜻을 알려 준다. 생각의 흐름을 한 단계씩 설명한다. |
| 고등학생 | 어느 정도 복잡한 내용을 다룰 수 있다. 정확한 용어를 쓰고 뜻을 설명한다. 미국 대학 입학시험(SAT) 수준의 어휘도 쓸 수 있다. |
| 대학생 | 학문적 맥락을 잡아 준다. 기술 용어에는 짧은 설명을 붙이고 이론과 실제 적용을 연결한다. |
| 대학원생 | 기초 지식이 충분하다고 본다. 미묘한 차이, 절충점, 경계 사례, 더 깊은 함의를 정확히 설명한다. |

### 직무

| 대상 | 관심사 | 설명의 초점 |
|---|---|---|
| 관리자 | 영향, 일정, 위험, 비용 | 사업 결과, 팀에 미치는 영향, 필요한 결정 |
| 엔지니어 | 동작 원리, 아키텍처, 절충점 | 기술 세부 사항, 구현, 성능, 유지보수성 |
| 디자이너 | 사용자 경험, 시각적 영향, 흐름 | 사용자에게 미치는 영향, 상호작용 방식, 접근성 |
| 임원 | 전략, 투자 대비 수익, 경쟁 우위 | 전체 그림, 시장에서의 위치, 자원 배분 |
| 동료 | 실무 맥락, 함께 하는 일 | 업무에 미치는 영향과 협업에 필요한 정보 |
| 제품 관리자 | 사용자 가치, 우선순위, 범위 | 기능의 영향, 사용자 스토리, 구현 범위와 제외 항목 |

### 관계

| 대상 | 말투 | 비유 방식 |
|---|---|---|
| 아내, 남편, 연인 | 따뜻하고 대화하듯 차분하게 | 집안일, 함께 겪은 일, 일상 습관 |
| 아버지, 어머니, 부모님 | 존중하며 분명하게 | 익숙한 기술, 가정생활, 세대가 공감하는 사례 |
| 아이 | 장난스럽고 격려하는 말투로 짧게 | 게임, 만화, 학교, 동물 |
| 친구 | 편하게, 어울리면 유머도 섞어서 | 대중문화, 공통 관심사, “그거 알지?” |

대상이 명시되지 않으면 기본 ELI5 방식인 5세 수준에 맞춘다.

## 2단계. 원본 자료 읽기

설명하기 전에 대상 내용을 충분히 이해한다.

- **코드**는 관련 파일을 읽고, 쉽게 풀어 쓰기 전에 전체적으로 무슨 일을 하는지 파악한다.
- **개념**은 핵심 요소로 나눈다.
- **오류 메시지**는 문구를 넘어 근본 원인을 파악한다.
- **기술 문서**는 독자에게 중요한 핵심을 추린다.
- **그 밖의 자료**는 무엇이며 왜 중요한지 파악한다.

## 3단계. 설명 만들기

대상에 맞춰 다음 원칙을 적용한다.

### 구성

1. **무엇인지 먼저 말한다.** 핵심을 한 문장으로 잡는다.
2. **비유를 쓴다.** 듣는 사람이 이미 아는 것과 연결한다.
3. **필요한 세부 내용을 더한다.** 이해 수준에 맞는 만큼만 설명한다.
4. **듣는 사람에게 어떤 의미인지 말한다.** 그 사람에게 왜 중요한지 짚고 마무리한다.

### 표현 수준

**어린아이, 비기술 직무, 가족처럼 쉬운 설명이 필요한 사람**

- 전문 용어는 피한다. 꼭 써야 한다면 바로 뜻을 설명한다.
- 한 문장에는 한 가지 생각만 담는다.
- 추상적인 설명보다 구체적인 비유를 쓴다. “서버는 식당에서 주문을 받아 주는 직원과 같아”라고 하면 “서버는 클라이언트와 서버 간 통신을 처리해”보다 이해하기 쉽다.
- 듣는 사람에게 직접 말하듯 설명한다. “네가 주문하면”처럼 그 사람의 상황과 연결한다.

**엔지니어, 대학원생처럼 기술 배경이 있는 사람**

- 정확한 전문 용어를 쓴다. 이미 아는 내용을 지나치게 쉽게 풀면 상대를 낮춰 보는 인상을 줄 수 있다.
- 절충점, 경계 사례, 설계 결정처럼 관심을 가질 부분에 집중한다.
- 상대가 아는 개념과 비교한다. “해시 맵과 비슷하지만 이 부분이 다릅니다”처럼 설명한다.
- 상대의 배경지식을 존중하고 간결하게 말한다.

**관리자, 임원처럼 사업 관점에서 판단하는 사람**

- 영향과 결과를 먼저 말한다.
- 가능하면 수치로 보여 준다.
- 요청받은 경우 구현 세부 사항을 설명한다.
- “이 결과를 보면 우리가 할 일은 …입니다”처럼 결정과 연결한다.

### 말투 맞추기

- **5~10세**는 좋아하는 선생님처럼 신나게 말한다. “와, 이건 재밌는 거야!”
- **청소년**에게는 조금 편하게 말한다. 억지로 또래인 척하는 말투는 피한다.
- **전문가**에게는 자신 있고 분명하게 설명한다. 상대의 지식을 존중하면서 필요한 배경을 보충한다.
- **가족**에게는 저녁 식사 중 이야기하듯 따뜻하고 차분하게 설명한다.

## 예시

**사용자 요청** “데이터베이스 인덱스가 뭔지 5살도 이해하게 설명해 줘.”

**대상** 5세, 기본값

**설명 예시** “수천 쪽이나 되는 아주아주 큰 책이 있다고 생각해 봐. 공룡이 나오는 쪽을 찾으려면 책장을 한 장씩 넘길 수도 있지만, 앞에 있는 목차를 보면 되잖아! 데이터베이스 인덱스는 그 목차와 같아. 컴퓨터가 전부 살펴보지 않아도 원하는 걸 아주 빨리 찾게 도와줘.”

**사용자 요청** “이 API 요청 제한을 우리 관리자에게 설명해 줘.”

**대상** 관리자

**설명 예시** “API에는 속도 제한이 있습니다. 분당 요청을 100건까지만 보낼 수 있는데, 이용이 몰리는 시간대에 한도에 도달해 일부 사용자 요청이 실패합니다. 요청 횟수를 줄이도록 코드를 개선하거나, 한도가 더 높은 요금제를 쓸 수 있습니다. 코드 개선에는 1~2일이 걸리고 상위 요금제는 월 X달러입니다. 제 추천은 …입니다.”

**사용자 요청** “이 React의 `useEffect` 훅을 대학생이 이해할 수 있게 설명해 줘.”

**대상** 대학생

**설명 예시** “`useEffect`는 React가 부수 효과를 다루는 방법입니다. API 호출, 구독, DOM 조작처럼 일반적인 렌더링 과정 밖에서 일어나는 일을 말합니다. 클래스 컴포넌트를 배웠다면 `componentDidMount`, `componentDidUpdate`, `componentWillUnmount`를 합친 생명주기 훅에 비유할 수 있습니다. 의존성 배열이 언제 다시 실행할지 결정합니다.”

## 기억할 점

- 누구에게도 얕보는 말투를 쓰지 않는다. 5세에게는 재미있게, 관리자에게는 스스로 판단할 수 있게 설명한다.
- 코드는 목적을 먼저, 동작 원리를 그다음에 설명한다. 왜 있는지 알아야 문법도 의미가 있다.
- 주제가 복잡하고 듣는 사람이 기술에 익숙하지 않다면 과감히 단순화해도 된다. 100% 정확하지만 이해하기 어려운 설명보다 80% 정확하더라도 핵심을 이해하게 하는 설명이 낫다.
- 설명 길이도 대상에 맞춘다. 어린아이에게는 짧고 쉽게, 깊이를 원하는 기술 독자에게는 세부 내용을 더한다.
