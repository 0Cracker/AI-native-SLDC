# 실행 경로와 단계 전환

- 제품 변경은 00 → 01 → 02 → (03 → 04 → 05 → 06a 반복) → 06b로 진행한다. 배포 대상은 07 → 08로 이어진다.
- Spike·PoC는 실험 기록과 반영 판단으로 종료한다. 제품 반영은 새 00에서 시작한다. 긴급 안정화는 부여된 사고 대응 권한에 따라 실행하고 근거를 남긴다. 신규 수정의 배포는 제품 변경 경로를 따른다.
- [축약 경로](compact-routes.md)에서 새로 기록할 항목과 참조로 충족할 조건을 고른다. 재개와 상위 변경의 영향 판정은 [재개·재검증](resume-and-recheck.md)을 따른다.
- 판정은 통과·실패·차단·승인된 예외로 기록한다. 승인된 예외는 승인 범위와 대체 증거, 잔여 위험을 남긴다. 승인에 다음 단계 진행이 포함되고 나머지 기준을 충족할 때만 진행한다. 승인 범위를 넘으면 차단한다. 미실행 검사는 통과로 집계하지 않는다.
- 상위 결정이 바뀌면 영향을 받는 판정과 증거를 다시 확인한다. 테스트 문제는 기대값 근거와 검사 방식의 원인을 나눠 복귀한다.

## 단계별 종료 조건

00~03은 [인터뷰 규칙](planning-interview.md#0003에서-다음-단계로-넘어가는-기준)을 따른다. 적용 조건을 모두 충족하고 증거를 대상 범위나 리비전에 연결하면 전환한다. 미충족 시 원인과 해소 조건을 기록한다.
