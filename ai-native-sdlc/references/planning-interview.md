# 00~03 사용자 인터뷰

1. 요청과 기존 근거로 초안을 작성한다. 사실, 제안, 확정 결정, 미결을 구분한다.
2. 코드·로그·문서로 확인할 사실은 직접 조사한다. 현행 동작과 확정 계약이 다르면 차이를 보여주고 기준을 확인한다.
3. 범위, 기대 행동, UX, 계약·호환성, 데이터, 권한, 비용·운영 위험을 바꾸는 결정은 먼저 묻는다. 한 번에 중요한 질문 1~3개를 제시하고 대안별 영향을 설명한다.
4. 답변으로 바뀐 내용과 남은 질문을 돌려준다. 충돌이나 새 영향이 생기면 후속 질문을 한다.
5. 사용자 결정이 필요한 작업은 보류하고 독립 조사는 이어간다. 침묵과 현행 동작은 승인 근거가 될 수 없다.

## 00~03에서 다음 단계로 넘어가는 기준

- 중요한 미결이나 바뀐 결정만 다시 확인한다. 범위와 전제가 같은 기존 결정은 재사용한다.
- 미결이 범위나 검증을 바꾸면 차단한다. 사용자가 범위를 좁히거나 보류하면 이유와 재개 조건을 기록한다.
- 종료 조건을 충족하면 근거를 요약하고 진행한다. 별도 승인이 요구되면 해당 규칙을 따른다.

| 단계 | 사용자와 맞출 내용 | 확인 자료 |
|---|---|---|
| 00 | 사용자, 문제, 목표, 범위, 성공 기준 | 문제 사례, 현재 우회 방법 |
| 01 | 정상·예외 동작, 유지할 계약, 기대 결과 | 시나리오, 인수 조건, 기대값 근거 |
| 02 | 구조 대안별 사용자 영향, 비용, 운영·복구 절충 | 경계도, 품질 시나리오, 실험 |
| 03 | 계약, 상태·예외, 데이터 의미, 권한과 복구 | 영향 영역별 그림, 입출력, 상태표와 검사 |

질문, 결정자, 근거, 상태와 영향 ID는 `intake.md` 또는 해당 요구·아키텍처·상세 설계의 정본에 남긴다. [종료 조건](lifecycle.md#단계별-종료-조건)으로 돌아간다.
