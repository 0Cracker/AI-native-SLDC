# 다이어그램 작성과 저장

- 02·03의 영향 영역마다 편집 가능한 그림을 작성·갱신하거나 유효한 기존 그림을 참조한다. 03의 C·H는 영향 여부를 항상 확인한다.
- 기존 그림은 이름, 책임, 경계, 계약 버전, 적용 범위를 대조한다. 한 그림이 여러 영역을 설명하면 영역별 적용 부분을 기록한다.

| 단계와 영향 영역 | 우선 선택하는 그림 | 그림에서 읽을 수 있어야 하는 것 |
|---|---|---|
| 02 시스템 경계, 외부 연동 | 시스템 컨텍스트 | 사용자, 외부 시스템, 신뢰와 책임 경계 |
| 02 서비스와 의존성 | 컨테이너·컴포넌트 관계도 | 서비스 책임, 연결 방향, 주요 계약 |
| 02 런타임, 배포 환경 | 런타임 시퀀스 또는 토폴로지 | 프로세스·환경, 통신, 실패 지점 |
| 03-A 데이터 | 도메인 관계도, ERD 또는 데이터 흐름도 | 소유권, 관계와 카디널리티, 저장·변환 경로 |
| 03-B 인터페이스 | 호출 시퀀스 또는 이벤트 흐름도 | 제공자와 호출자, 정상·오류, 변경 계약 |
| 03-C 컴포넌트 | 컴포넌트 관계도 또는 상태 전이도 | 책임, 의존성, 상태 전이와 불변조건 |
| 03-D UX | 사용자 흐름도, 화면 상태 전이도 또는 와이어프레임 | 진입, 주요 조작, 빈 상태·오류·복구 |
| 03-E AI | Agent·Tool 흐름도 또는 RAG 데이터 흐름도 | 모델과 Tool 역할, 근거, 권한과 Fallback |
| 03-F 보안 | 신뢰 경계가 표시된 데이터 흐름도 | 민감 데이터 경로, 권한 검사, 신뢰 경계 |
| 03-G 운영 | 배포 토폴로지 또는 이행·복구 흐름도 | 단계별 중단 조건, 검증과 복구 경로 |
| 03-H 검증 | 검증 경계도 또는 요구와 테스트 관계도 | 검사 대상, 관측 지점, 인수 조건과 테스트의 연결 |
| 03 확장 영역 | 관련 관계도, 결정 흐름도 또는 상태 전이도 | 확장 영역의 책임과 경계, 정상·예외 경로, 검증 지점 |

- 기존 편집 형식을 우선한다. 새 그림의 기본 형식은 Mermaid `.mmd`다. 필요하면 검토용 이미지를 함께 제공한다.
- 공통 그림은 공통 루트의 `diagrams/`, Feature 그림은 `architecture/diagrams/` 또는 `designs/diagrams/`에 둔다. [산출물 구조](artifact-layout.md)를 따른다.
- 해당 A·D 문서에 상대 경로, 영역·Increment, 작성·갱신·참조 상태, 적용 범위, 계약·검증 ID를 연결한다. 필요하면 현행과 변경안을 구분한다.
- 가능한 경우 파싱·렌더링을 확인한다. 미확인은 기록하고, 그림 내용과 검증 결과는 따로 판단한다. 누락된 영향 영역은 해당 Gate에서 보강한다.
